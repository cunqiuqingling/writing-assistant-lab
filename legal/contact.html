区分公开Issue和私密安全、凭据、版权渠道，避免敏感材料被公开。

生效日期：2026年7月28日 · 最近更新：2026年7月28日

一般问题与功能反馈

功能问题、复现步骤、界面建议和非敏感文档可提交到公开GitHub Issues。提交前请删除API密钥、个人身份信息、未公开论文、患者资料及受限制文件内容。

新建GitHub Issue适合Bug、功能建议和一般公开讨论。 查看项目仓库查看源代码、版本记录、许可证与已有Issue。

安全、凭据与版权事项

可直接利用的漏洞、泄露凭据、身份材料和版权证明不应发到公开Issue。请优先使用Private Vulnerability Reporting（如果页面提供入口），或通过维护者GitHub资料中的私密联系方式联系。

私密安全报告入口可用时，用于漏洞和敏感安全信息。 维护者GitHub资料查看维护者公开提供的联系方式。

提交信息建议

  • 写明涉及页面、版本和问题类型；
  • 提供最小复现步骤，不附带真实密钥或无关个人数据；
  • 版权事项说明作品、权利基础、准确位置和希望采取的措施；
  • 不要发送与问题无关的大型受保护文件。
后续改进

在面向更大范围推广或开展商业运营前，项目宜配置独立域名邮箱，用于安全、版权和法律通知。

English summary

Use public GitHub Issues for ordinary feedback. Security vulnerabilities, credentials, identity documents and copyright evidence must use a private channel.

Writing Assistant 是本地优先的开源英语写作练习工具。政策文本用于说明当前产品行为，不构成针对任何人的法律意见。
