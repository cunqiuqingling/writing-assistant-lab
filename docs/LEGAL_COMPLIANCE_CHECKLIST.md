# Legal and compliance maintenance checklist

Last reviewed: 2026-07-28

This is an internal checklist, not a legal opinion.

## Public disclosures

- [x] Privacy, terms, copyright, security, third-party and contact pages.
- [x] Links from the product footer.
- [ ] Add a dedicated domain email before broad commercial or institutional promotion.
- [ ] Re-review when accounts, payment, analytics, backend processing or default AI behavior changes.

## Deployment and filing

- [ ] Do not state that Cloudflare hosting or a static architecture automatically removes filing obligations.
- [ ] Do not display an ICP number that has not been validly obtained.
- [ ] Reassess filing before using mainland-China infrastructure, charging, operating institutionally or conducting broad formal promotion.
- [ ] Confirm the position with the actual access provider or qualified counsel when deployment changes.

## AI

- [x] Core practice works without AI.
- [x] BYOK is user-configured and user-triggered.
- [x] Intended requests exclude learner writing, notes, plans and progress.
- [ ] If a default provider, server proxy, shared key or public generative service is added, reassess filing/registration, model disclosure, content governance and privacy before launch.
- [ ] Do not describe BYOK as categorically exempt from all AI regulation.

## Copyright and security

- [x] Original IELTS-style content is identified as unofficial.
- [x] Takedown notice and private evidence route are documented.
- [ ] Maintain a source/license inventory for every new text, image, font, model and dataset.
- [ ] Enable GitHub Private Vulnerability Reporting.
- [ ] Require passkey or 2FA on GitHub, Cloudflare and the domain registrar.
- [ ] Consider a tested CSP only after verifying BYOK, Workers, WASM, Wikimedia and loopback access.
